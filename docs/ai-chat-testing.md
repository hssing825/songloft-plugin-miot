# AI 对话测试与验收

关联需求：songloft-org/songloft-plugin-miot#119。本清单对应单插件内部重构、原有 AI 音乐口令分析保留、AI 对话，以及统一 AI 设置界面。

自动化测试验证确定的程序行为，不等于所有音箱固件、网络环境或模型回答质量都已验证。测试中的模型与设备替身用于控制超时、失败和异步返回顺序；原生播报、真实打断和分组同步仍需实机验收。

## 运行与判断

插件目录执行：

```bash
npx tsc --noEmit
node --experimental-strip-types --test tests/*.test.mjs
```

前端目录执行：

```bash
npm run typecheck
npm run build
npm test
```

需要查看某个测试文件内部的详细用例时，直接执行 `node --experimental-strip-types tests/chat_scenarios.test.mjs`。统计测试数量时区分测试文件数与测试用例数。无失败、无取消才算通过；挂起或跳过的用例不能算已验证。

构建插件并验证 ZIP 清单：`songloft-plugin build`；在 `dist/_build/` 执行 `../../node_modules/.bin/songloft-plugin validate`。

## 宿主和浏览器验证

使用隔离数据库与测试账号，在真实 Songloft / QuickJS 中上传构建后的测试插件，模型连接指向本地模拟服务。验证未登录访问被拒绝、文本问答与历史上下文、自动提取、慢响应取消、清空后迟到结果不写回、模型列表以及配置持久化。测试账号只写入隔离数据库，正式插件不包含假账号或测试初始化逻辑。

使用 Docker 无头浏览器验证统一 AI 设置在桌面和手机宽度下的渲染与交互。操作后读取后端状态，确认默认连接、问答开关与记忆确实保存；验证关闭分析仍能复用连接问答。截图和无横向溢出检查只证明显示行为，不代表音箱播报已验证。

## 必须实机确认

| 场景 | 验收标准 |
|---|---|
| 各型号原生 TTS | 正确出声，长回答逐段顺序播报；实际播完后设备状态可确认结束 |
| 小爱回答与 AI 接管 | 启动问答能打断原回答，取消/新问题不出现延迟重新出声 |
| 播放与位置 | 问答后从原曲进度恢复；原本暂停/停止不自行启动；倍速、电台行为符合原播放器规则 |
| 两台以上分组 | 全组音乐暂停，只在提问设备播报；跨设备控制取消旧恢复；离线成员不拖住其他成员 |
| 真实 DLNA 与定时动作 | 投放期间拒绝语音问答；新的投放、定时播放、睡眠到期不被旧问答恢复覆盖 |
| 不稳定网络 | 云服务超时、音箱掉线及恢复后不重复推送，不把未知播报状态判为完成 |
| 实际模型 | 音乐口令解析、连续追问、摘要和偏好提取质量符合预期；替身测试不能证明模型语义准确 |

实机项目在实际执行前保持“未验证”。本清单不宣称 100% 代码覆盖率或所有环境零缺陷。
